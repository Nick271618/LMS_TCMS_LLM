## Цель

Веб-LMS (аналог Stepik) для курсов по QA: теория, тесты, тест-кейсы, свободные ответы, практика на сгенерированных формах. **Локальная LLM (Ollama)** автоматизирует проверку работ и генерацию учебных объектов для тестирования — **без облачных API**.

## LLM: принцип работы

1. Преподаватель задаёт **рубрику** (критерии, веса, подсказки) в шаге урока.
2. Студент сдаёт работу → Django **собирает промпт** из шаблона + контекста + ответа.
3. **HTTP POST** на `http://127.0.0.1:11434/api/generate` (Ollama, `temperature=0`).
4. Модель возвращает **JSON** (проценты по критериям, итог, рекомендации).
5. Backend **пересчитывает** итог по весам, сохраняет балл; при сбое — ручная проверка.

**Типы шагов с LLM:** `test_case`, `free_answer` (оценка); `ui_practice` (генерация формы + оценка тест-кейса). Quiz/match — без LLM.

## Промпты (каталог `backend/apps/llm/prompts/`)

| Файл | Назначение |
|------|------------|
| `test_case_grade.txt` | Оценка тест-кейса по ТЗ и рубрике |
| `free_answer_grade.txt` | Оценка текстового ответа по рубрике |
| `generate_ui_practice.txt` | Генерация формы для ручного тестирования |

Сборка: шаблон + подстановка `{condition_html}`, `{rubric_text}`, работы студента и т.д. в `grading.py` / `generation.py`.

---

## Сценарии

**Преподаватель:** редактор урока → «Сгенерировать с ИИ» (форма login/register/CRUD) → предпросмотр черновика → шаг в уроке.  
**Студент:** тестирует форму → сдаёт тест-кейс → получает балл и рекомендации LLM.  
**Контроль:** `llm_debug` только для преподавателя; финальная оценка может быть скорректирована вручную.
