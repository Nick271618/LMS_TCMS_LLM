# Эталон (преподаватель). Задание 1 — Вход

> Не показывать студенту. Можно вставить в `reference_test_case` шага LMS.

## Эталон A — успешный вход

| Поле | Текст |
|------|-------|
| **Название** | Успешный вход с корректными email и паролем |
| **Предусловия** | Пользователь `student@demo.test` зарегистрирован, пароль `Demo1234!`, не авторизован. Открыта страница `/login`. |
| **Шаги** | 1. В поле Email ввести `student@demo.test`<br>2. В поле Пароль ввести `Demo1234!`<br>3. Нажать кнопку «Войти» |
| **Ожидаемый результат** | URL `/tasks`; заголовок «Мои задачи»; в шапке отображается имя пользователя; после F5 пользователь остаётся авторизованным. |

## Эталон B — неверный пароль

| Поле | Текст |
|------|-------|
| **Название** | Сообщение об ошибке при неверном пароле |
| **Предусловия** | Пользователь `student@demo.test` существует. Открыта `/login`. |
| **Шаги** | 1. Email: `student@demo.test`<br>2. Пароль: `WrongPass1`<br>3. Нажать «Войти» |
| **Ожидаемый результат** | Остаёмся на `/login`; текст «Неверный email или пароль»; поля формы доступны для повторного ввода. |

## Эталон C — пустой email

| Поле | Текст |
|------|-------|
| **Название** | Валидация пустого поля Email |
| **Предусловия** | Открыта `/login`. |
| **Шаги** | 1. Поле Email оставить пустым<br>2. Пароль: `любойпароль123`<br>3. Нажать «Войти» |
| **Ожидаемый результат** | Вход не выполнен; под полем Email текст «Укажите email». |

## Критерии приёмки работы студента

- Сценарий соответствует одному из требований ТЗ.
- Шаги воспроизводимы, ожидаемый результат проверяем.
- Нет лишних шагов (регистрация, соцсети).
