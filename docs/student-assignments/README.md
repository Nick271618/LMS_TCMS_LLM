# Учебные задания: тестовая документация и эталоны

Материалы для курса по основам тестирования ПО. Студенты составляют **один тест-кейс** на задание по полям LMS: название, предусловия, шаги, ожидаемый результат.

## Как использовать в LMS

| Роль | Действие |
|------|----------|
| **Преподаватель** | Создать шаг `test_case` → в **«Условие»** вставить HTML из файла `*-tz.html` (или текст из `*-tz.md`) → в **эталон** — поля из `*-reference-teacher.md` (не показывается студенту) |
| **Студент** | Читает только **Условие** на шаге, пишет свой тест-кейс, отправляет на проверку ИИ |

## Задание «Сопоставление» (тип шага `match`)

Автопроверка без ИИ — студент выбирает соответствие из выпадающего списка.

- Пример настройки: [04-match-example.md](04-match-example.md)

## Рекомендуемые баллы и рубрика

- Баллы за шаг: **10**
- Рубрика: дефолтная (5 критериев) или с hint: «обязателен негативный сценарий» для заданий 1–2
- Порог зачёта: **60%**

## Что проверяет ИИ

Соответствие **вашему ТЗ** в условии шага, а не «идеальному» тест-кейсу из учебника. Эталон нужен преподавателю и модели для полноты сценариев, студент его не видит.
