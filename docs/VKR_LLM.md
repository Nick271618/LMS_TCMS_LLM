# Автопроверка тест-кейсов локальной LLM (материал для ВКР)

## Цель

Снизить нагрузку на преподавателя при проверке учебных тест-кейсов и дать студенту **структурированную обратную связь** по критериям, привязанным к ТЗ задания, без облачных API.

## Архитектура

```
Преподаватель → Step (condition_html, rubric, reference_test_case*)
Студент → POST submit-test-case (4 поля)
Django → Ollama HTTP /api/generate → JSON
StepSubmission: score, feedback, grading_source=llm, payload.llm_grade
```

\* `reference_test_case` опционален, скрыт от студента.

**MCP в MVP не используется** — прямой вызов Ollama проще для воспроизводимости эксперимента. MCP описывается как перспектива чат-тьютора (tools: контекст шага, сдача, оценка).

## Модель и среда

| Параметр | Значение |
|----------|----------|
| Среда | Ollama, локально |
| Модель по умолчанию | `qwen2.5:7b-instruct-q4_K_M` |
| ОЗУ | ~8 ГБ (квантизация Q4) |
| temperature | 0 |
| num_ctx | 4096 |
| Таймаут | 120 с |

Запасные модели: `llama3.2:3b-instruct-q4_K_M`, `phi3:mini-4k-instruct-q4_K_M`.

## Критерии рубрики (каталог)

| ID | Название | Вес по умолчанию |
|----|----------|------------------|
| `tz_alignment` | Соответствие тестовой документации | 30% |
| `structure` | Структура и полнота полей | 20% |
| `steps_quality` | Качество шагов | 25% |
| `expected_result` | Ожидаемый результат | 15% |
| `preconditions` | Предусловия | 10% |

Преподаватель в редакторе шага включает/выключает критерии, задаёт веса, `hint` на критерий, `free_text` и `pass_percent`. Студент видит только **результат** проверки (баллы, summary, рекомендации, проценты по критериям).

## Формула балла

`score = round(max_score × total_percent / 100)`, где `total_percent` — взвешенное среднее процентов по включённым критериям (пересчитывается на бэкенде по ответу модели).

## Поля тест-кейса студента

- `title` (обязательно)
- `preconditions` (опционально)
- `execution_steps` (обязательно)
- `expected_result` (обязательно)

Убраны поля TMS: `test_case_id`, `description`, `priority`, `testing_type`.

## Ответ модели (JSON)

```json
{
  "total_percent": 72,
  "criteria": [
    { "id": "tz_alignment", "percent": 80, "comment": "..." }
  ],
  "summary": "Краткий итог",
  "recommendations": ["Совет 1", "Совет 2"]
}
```

При ошибке парсинга или недоступности Ollama: `status=submitted`, `payload.llm_error`, ручная оценка в кабинете.

## Риски и митигация

| Риск | Митигация |
|------|-----------|
| Галлюцинации | Жёсткий JSON, критерии из каталога, опора на `condition_html` |
| Нестабильность оценок | `temperature=0`, лог `llm_debug` (только преподаватель) |
| Субъективность | Рубрика и hints от преподавателя; финал — ручная оценка |
| Утечка промпта | `llm_debug` не отдаётся студенту |

## Эксперимент для главы «Результаты»

1. 10–15 сдач одного задания.
2. Оценка преподавателем (слепая или после ИИ — зафиксировать протокол).
3. Метрики: корреляция баллов, расхождение по критериям, время проверки.
4. Качественный разбор типичных ошибок модели.

## Запуск

```powershell
ollama pull qwen2.5:7b-instruct-q4_K_M
ollama serve
```

В `backend/.env`: блок `OLLAMA_*` из `.env.example`.

## Генерация объектов для тестирования (ui_practice)

### Сценарий преподавателя

1. Редактор урока → **«Сгенерировать с ИИ»**.
2. Промпт, например: «Форма входа: email, пароль, чекбокс "Запомнить"».
3. Ollama возвращает JSON: `task_html`, `fields`, `form_html`, `rubric`, `reference_test_case`.
4. Черновик `StepDraft` → предпросмотр `/teach/preview/draft/:token`.
5. **«Добавить в урок»** → `Step(step_type=ui_practice)`.

### API

| Метод | URL |
|-------|-----|
| POST | `/api/llm/generate-ui-practice/` |
| GET | `/api/llm/step-drafts/preview/:token/` |
| POST | `/api/llm/step-drafts/:id>/confirm/` |
| POST | `/api/steps/:id/submit-ui-practice/` |

### Сценарий студента

1. Открывает шаг в `/learn/:courseId?lesson=&step=`.
2. **Объект тестирования** — интерактивная форма (поля из `fields`).
3. **Сдать тест-кейс** — те же 4 поля, что у `test_case`.
4. LLM оценивает по рубрике; в промпт попадает описание формы (`task_html` + `fields`), а не только `condition_html`.

### Пример промпта

```
Сгенерируй форму регистрации: имя, email, пароль, подтверждение пароля, кнопка «Зарегистрироваться».
Добавь 1–2 учебных дефекта в валидации.
```
