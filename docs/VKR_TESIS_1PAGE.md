# LMS для обучения тестированию ПО — тезисы (1 стр.)

**Студент:** _ФИО_ · **Тема ВКР:** LMS с локальной LLM для проверки учебных работ  
**Стек:** Django 6 + DRF + JWT · React/TS + Vite · PostgreSQL · **Ollama (локально)**

---

## Назначение системы

Stepik-подобная LMS: курсы → модули → уроки → **шаги** (теория, тест, тест-кейс, сопоставление, свободный ответ, UI-практика). Роли: преподаватель (контент, рубрики, проверка), студент (прохождение, сдача). **Ключевая новизна:** автопроверка работ локальной LLM без облачных API + генерация учебных форм для ручного тестирования.

## Технологии (краткое обоснование)

| Компонент | Зачем |
|-----------|--------|
| Django + DRF | Backend, REST API, ORM |
| SimpleJWT | Авторизация SPA |
| PostgreSQL | Надёжное хранение данных |
| React + TypeScript | Интерактивный интерфейс |
| Ollama + Qwen/Llama 3B–7B | LLM локально, офлайн, бесплатно |
| JSON-рубрики в шагах | Гибкая настройка без миграций |

## LLM: принцип работы

1. Преподаватель задаёт **рубрику** (критерии, веса, подсказки) в контенте шага.  
2. Студент сдаёт работу → Django собирает **промпт** из шаблона + ТЗ + рубрика + ответ.  
3. **POST** `http://127.0.0.1:11434/api/generate` (Ollama): `model`, `prompt`, `temperature=0`.  
4. Модель возвращает **JSON** (`total_percent`, `criteria[]`, `summary`, `recommendations`).  
5. Backend пересчитывает итог по весам, сохраняет балл; при сбое — ручная проверка.

**Типы с LLM:** `test_case`, `free_answer` (шкала порогов баллов), `ui_practice` (генерация формы + проверка тест-кейса).

## Ограничения и эксперимент

Малые модели (3B) — риск невалидного JSON и субъективности; mitig.: жёсткий формат, пересчёт на backend, `llm_debug` только для преподавателя. **План:** 10–15 сдач, сравнение оценок LLM и преподавателя, метрики корреляции и времени проверки.
